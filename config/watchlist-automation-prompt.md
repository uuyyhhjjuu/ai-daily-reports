## 覆盖范围
前一日 21:00 至当日 21:00（北京时间）。每只标的收集三类信息：
① 公司公告：业绩与指引、回购/增减持、重大合同与投资、监管处罚、人事变动、停复牌；
② 权威媒体报道：产品与业务进展、渠道与高频经营数据、行业供需与价格变化；
③ 覆盖券商观点变化：评级或目标价的调整（仅记录变化本身，不展开研报正文）。以中文信息为主，重要的海外动态（如外资行调整）须覆盖。

## 执行步骤
1. 仓库路径：C:\Users\86151\WorkBuddy\自动化任务\ai-daily-reports（git，remote git@github.com:uuyyhhjjuu/ai-daily-reports.git，分支 main，GitHub Pages 源）。
2. 确定雷达日期 D（运行当日，YYYY-MM-DD）。若 D 的雷达页已存在，则改为补生成 radar 目录中缺失的最近一个日期。
3. 【信息拉取】优先使用已连接的金融数据能力（腾讯自选股/Wind/进门投研/Alpha派等连接器或技能）查询每只标的的当日公告、新闻与研报评级变化；再用 WebSearch 按「标的名称 + 公告/新闻/目标价」逐只补充检索。每只标的至少独立检索一轮；当日确实无事件的标的，如实标注「今日无新增事件」。严禁编造事实、数字或链接。
4. 【预筛（三态）】PASS＝与该标的直接相关的实质事件；BLOCK＝无关内容或纯股价涨跌描述（无明确催化不入选）；UNKNOWN＝材料不足，保留待补，不直接丢弃。只有 PASS 进入评分。
5. 【重要性评分】对每条 PASS 事件打 0–100 重要性分，四轴各 0–10（权重和为10）：sig 实质份量×3 / nov 信息增量×2 / cred 证据强度×2 / impact 对股价与基本面的影响×3。压噪声上限：例行小额回购且无新信息 sig≤4；转述旧闻或重复已知信息 nov≤3；无数据来源的"传闻+据说"类 cred≤3。≥60 分进正文分节，40–59 分进"当日要闻表"。
6. 【事件卡片】每条含：标的名称与代码、事件标题、重要性分、中文摘要（数字必须与来源一致）、来源名称与日期、可点击原文链接。对比最近 7 天雷达页：同一事件的实质新进展在标题前标「⬆」，全新事件标「🆕」。
7. 【生成页面】以最近一份雷达页为模板（ai-daily-reports/radar/ 下取最新；若无则参照最新 AI 日报页的 CSS 与风格），路径 ai-daily-reports/radar/YYYY-MM/覆盖池雷达-YYYY-MM-DD.html。页面结构：头部「今日焦点」Top3 一句话导语 → 按标的分节（有事件的按最高分事件排序）→ 当日要闻表 → 底部「今日无新增事件」标的列表。
8. 原子同步更新 ai-daily-reports/radar/index.html：按时间倒序插入当日条目，月分组标题「📅 2026 年 X 月」。雷达页与 radar/index.html 必须在同一次 commit 中提交。
9. git add / commit / push 到 main 分支。注意：若沙箱拦截 ~/.ssh 导致 push 静默失败，必须用绕过沙箱（dangerouslyDisableSandbox）的方式重新执行 git push，并验证输出中出现 "main -> main"。

## 硬性要求
- 时间格式：实时生成用「X小时前 / 今天HH:MM / 昨天HH:MM」；补生成历史日期用绝对日期。
- 不生成 PDF。
- 磁盘保护：写文件前先 df -h /c；若可用空间 < 1GB，停止生成，仅在结果中报告「磁盘不足，雷达未生成」，严禁继续写文件（防止 ENOSPC 把文件截断为 0 字节）。
